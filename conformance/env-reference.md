# Configuration reference for maintainers

This inventory records where the pinned reference implementation reads environment settings. User-facing setup and the precedence applied in Go are in [environment configuration](../docs/environment.md).

| Reference source | Inputs and scope |
| --- | --- |
| [Context construction](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/better-auth/src/context/create-context.ts) and [secret parsing](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/better-auth/src/context/secret-utils.ts) | Explicit configuration, `BETTER_AUTH_SECRETS`, `BETTER_AUTH_SECRET`, `AUTH_SECRET`. The first versioned entry is current. Go also accepts the neutral plural alias. Go rejects short keys at startup and explicitly supports overlapping cookie and email-signature verification keys. |
| [URL resolver](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/better-auth/src/utils/url.ts) | Explicit URLs, `BETTER_AUTH_URL`, three public framework aliases, `NUXT_PUBLIC_AUTH_URL`, `BASE_URL`. A lone slash is skipped. The Go implementation also accepts `AUTH_URL` and requires a configured public origin. Request-derived origins and wildcard hosts are separate capabilities. |
| [Client URL resolution](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/better-auth/src/client/config.ts) | The vanilla client checks shared URL aliases, then `NEXT_PUBLIC_AUTH_URL`, server-side `NEXTAUTH_URL` and `VERCEL_URL`. The first two supply a complete mount. Vercel supplies an origin. Browser clients can issue relative requests with an implicit origin. The native Go client requires a host. The Go-specific `AUTH_URL` also works for native clients. |
| [Origin configuration](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/better-auth/src/context/helpers.ts) | The comma-separated `BETTER_AUTH_TRUSTED_ORIGINS` augments configured origins. |
| [Runtime environment](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/core/src/env/env-impl.ts) | `NODE_ENV` influences production defaults. Go reads this for rate limiting and default error redirection, with an `AUTH_ENV` override. The pinned test-mode detector also reads `TEST` and skips default secret validation in tests. Go requires a strong secret in every mode. |
| [Telemetry](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/telemetry/src/index.ts) | `BETTER_AUTH_TELEMETRY`, `BETTER_AUTH_TELEMETRY_DEBUG`, `BETTER_AUTH_TELEMETRY_ENDPOINT` and the core telemetry-ID accessor concern instrumentation. The Go library has no telemetry exporter. The name `BETTER_AUTH_TELEMETRY_DISABLED` occurs in reference CLI tests. |
| [OAuth proxy](https://github.com/better-auth/better-auth/blob/v1.7.27/packages/better-auth/src/plugins/oauth-proxy/utils.ts) | `VERCEL_URL`, `NETLIFY_URL`, `RENDER_URL` and cloud function detection belong to that optional integration. They do not select the Go API origin. |
| Managed infrastructure documentation | `BETTER_AUTH_API_KEY`, `BETTER_AUTH_API_URL`, `BETTER_AUTH_KV_URL` configure separately hosted services. The local library requires no hosted account. |
| Build and documentation examples | `BETTER_AUTH_VERSION` is build metadata. `BETTER_AUTH_ACCEPT_METHODS` is a code example's array. Neither is an application runtime setting. |

Provider secret names in examples generally describe the host app passing an explicit option. Add an automatic lookup only when the target package actually reads it, and exercise it through a real caller before checking the feature off.
